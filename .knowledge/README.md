# Current Knowledge Root

This repository-owned root contains only current authoritative truth about the system. Knowledge
nodes use typed frontmatter and may map to behavior-bearing paths through `appliesTo`.

Domain knowledge may additionally be organized as an entity ontology under `entities/<id>/`, opt-in
per constitution Principle I — see [tooling/developer-guide.md](tooling/developer-guide.md) and
[tooling/content-lifecycle.md](tooling/content-lifecycle.md) for authoring guidance, and
`ontology/coverage.json` for the generated per-entity layer-coverage report.

Cross-cutting decisions ("what did we choose, and why not the alternatives") live in
[governance/decisions/](governance/decisions/) — current governance, edited in place, never a
history log; see [governance/decisions/README.md](governance/decisions/README.md).

Update knowledge in the same change as the code and tests it describes. Delete obsolete content
instead of retaining historical copies, decision logs, rationale archives, lifecycle states, or
supersession chains. Git is the sole history.

`index.json` is generated by `scripts/build_knowledge_index.py` and is the machine-readable entry
point. Framework install and upgrade must never modify this root.
