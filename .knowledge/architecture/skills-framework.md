# Command and Skill Boundary

DevSpark is a lifecycle orchestrator that can host portable Agent Skills. It is not a competing
skills specification.

Commands own repository lifecycle, governance, artifact placement, routing, and handoffs. Skills own
portable capability instructions that can execute independently of DevSpark repository state.
A command may delegate a bounded capability to a skill through an adapter, but the command retains
responsibility for lifecycle rules and durable outputs.

A shipped skill must have valid metadata, self-contained instructions, declared inputs and outputs,
and portable scripts where execution is required. Adapters translate command context into the skill
contract without embedding DevSpark-only lifecycle assumptions inside the skill.

## Generated Command Skills

Every stock command is also published as a thin, generated Agent Skill named `devspark-<command>`
under `templates/consumer-skills/devspark-<command>/SKILL.md`. These are distinct from the helper
skills under `templates/skills/`: a command skill carries no command instructions. Its body holds a
fixed generated marker, resolves the command through the existing developer, team and default chain
(`.devspark.work/{git-user}/commands/devspark.<command>.md`, then
`.devspark.work/commands/devspark.<command>.md`, then
`.devspark/defaults/commands/devspark.<command>.md`, first existing file wins), and passes the text
typed after the skill name to the resolved prompt as the command input. The skill carries no
`handoffs`; its frontmatter is exactly `name`, `description`, `user-invocable` and
`disable-model-invocation`.

The Bash and PowerShell generators (`generate-atomic-shims`) emit these skills and are the only
writers; the two outputs are byte-identical and `--check` / `-Check` fails on any drift or orphaned
folder. Hand edits are overwritten on regeneration. Override filenames keep their dotted
`devspark.<command>.md` names.

The source repository dogfoods the same names through `.github/skills/devspark-<command>/SKILL.md`,
generated by the same tool. Those skills route directly to `templates/commands/<command>.md`; the
five commands that only apply to a consumer repository (`add-application`, `list-applications`,
`discover-constitution`, `personalize`, `upgrade`) instead carry the stop body kept in
`eng/skills/source-stop/<command>.md`, which is their single source. There are no agent or prompt
shims.
