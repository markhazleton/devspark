# DevSpark Documentation Guidance

DevSpark documentation must describe a prompt-first product.

Install, upgrade, and repair instructions must point to quickstart prompts in
`quickstart/`. Do not document a DevSpark command-line application or terminal
maintenance path.

Keep durable project truth in `.knowledge/`, framework stock assets in
`.devspark/`, and temporary lifecycle work in `.devspark.work/`.
