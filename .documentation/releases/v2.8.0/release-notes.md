## Highlights

DevSpark 2.8.0 adds a traceability and anti-gaming layer without migrating any
existing JSON contract. Lifecycle scripts now emit OKF Markdown knowledge
documents under each feature's `knowledge/` folder while preserving the JSON
responses current consumers already parse.

The release also adds advisory knowledge-coverage validation to `/devspark.analyze`
and `/devspark.critic`, plus Genuine Fix Discipline across review, fix, audit,
and verification commands. Findings now preserve behavioral intent so a fix must
prove the behavior changed, not just that a metric went down.

## New Features

### OKF Knowledge Documents

Feature creation and plan setup dual-write Markdown knowledge documents with YAML
frontmatter under `.documentation/specs/<feature>/knowledge/`. The frontmatter is
validated by `templates/schemas/okf-knowledge-document.schema.json`, and the
legacy JSON outputs remain unchanged.

### Knowledge-Coverage Validation

New Bash and PowerShell validators report requirement, task, and gate-evidence
coverage. `/devspark.analyze` and `/devspark.critic` run the validator as an
additive, fail-soft pass and skip cleanly when a feature predates the knowledge
layer.

### Genuine Fix Discipline and `/devspark.verify`

`templates/command-preamble-contract.md` now includes Section 9 guidance for
behavior-first fixes, an intent-cue table, cross-language notes, and a
constitution-citation hook. Analyze and critic findings carry `intent_cue`,
site-audit findings carry `Intent`, and `/devspark.verify` fails proofs that only
show metric movement with unchanged behavior.

### `/devspark.fix-score`

The new score-remediation command diagnoses repository score blockers and applies
fixes without weakening score rules. Companion context scripts support the command
surface and release package coverage.
