## Highlights

This release hardens the DevSpark Harness into a production-trustworthy execution engine.
The core change is a **dual outcome model** that separates orchestration completion
(`workflow_status`) from actual implementation delivery (`delivery_status`), eliminating
false-positive "complete" runs where no code or tests were produced.

A new **Adapter Doctor** subsystem gives hands-off runs deterministic adapter routing:
adapters now expose explicit capability states, and write-incompatible adapters fail fast
rather than silently degrading. Combined with the **Hands-Off Lifecycle Mode**, DevSpark
can now chain the full `plan → tasks → analyze → critic → implement → create-pr → pr-review`
pipeline without human intervention, publishing a decision packet and convergence report
for every run.

Governance and code-quality work rounds out the release: Constitution §VIII (Markdown
Quality) was ratified, `pip-audit` was wired into CI, and the bash/PowerShell script
surface now has full parity with the addition of `address-pr-review.sh`.

## Upgrade Guide

No breaking changes. Consumers running `devspark upgrade` will receive:

- Updated `.devspark/VERSION` stamp (2.2.0)
- New `templates/workflows/harness-strict-template.md`
- Updated atomic shims for address-pr-review

Existing harness YAML specs continue to work unchanged. Delivery gate defaults to
requiring `src/**` or `test/**` file mutations in implement stages; to opt-out per
workflow, set `delivery_evidence_required: false` in your workflow YAML.
