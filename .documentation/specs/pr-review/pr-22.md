### C-01 🔴 Open

**Principle**: II. Explicit Over Implied (NON-NEGOTIABLE)

**Location**: [src/devspark_cli/harness/runner.py](c:/GitHub/MarkHazleton/DevSpark/src/devspark_cli/harness/runner.py#L74), [src/devspark_cli/harness/runner.py](c:/GitHub/MarkHazleton/DevSpark/src/devspark_cli/harness/runner.py#L78)

**Issue**: `resolve_context()` catches every `ValueError` from `load_registry()` and silently falls back to `registry = None`. That means a malformed or path-invalid `.documentation/devspark.json` is treated the same as “no registry present”, so the runtime guesses repo/single-app behavior instead of surfacing the invalid multi-app context.

```python
        try:
            registry = load_registry(self.repo_root)
        except ValueError:
            registry = None
```

That is a direct violation of the constitution rule that ambiguous context must fail clearly rather than be inferred.

**Fix**: Only suppress the specific “registry not found” case. Propagate malformed-registry/path-validation errors as `HarnessSpecError`, or split `load_registry()` into “optional load” versus “validated load” APIs so missing and invalid registries are distinguishable.

### H-01 🔴 Open

**Principle**: II. Explicit Over Implied (NON-NEGOTIABLE)

**Location**: [src/devspark_cli/harness/runner.py](c:/GitHub/MarkHazleton/DevSpark/src/devspark_cli/harness/runner.py#L56)

**Issue**: When `repo_root` is not provided, the runner discovers the repository root from `Path.cwd()` instead of from the spec file location:

```python
        self.repo_root = Path(repo_root).resolve() if repo_root is not None else discover_repo_root(self.spec_path, Path.cwd())
```

This makes harness behavior depend on where the command is launched from. Running `devspark harness run C:\repo\sample.harness.yaml` from another directory can resolve root-relative paths like `.documentation/...` and `.devspark/...` against the wrong tree, even though the spec path itself is explicit.

**Fix**: Discover the repo root from `self.spec_path` by default, not the caller's current directory. If a cwd-based override is desired, it should be explicit and separate from spec resolution.

### H-02 🔴 Open

**Principle**: VI. Platform Parity

**Location**: [src/devspark_cli/harness/adapters/base.py](c:/GitHub/MarkHazleton/DevSpark/src/devspark_cli/harness/adapters/base.py#L54), [src/devspark_cli/harness/adapters/base.py](c:/GitHub/MarkHazleton/DevSpark/src/devspark_cli/harness/adapters/base.py#L55)

**Issue**: The real adapters pass the entire prompt text as a single command-line argument:

```python
    def build_command(self, prompt_text: str) -> list[str]:
        return [self.executable, "--print", prompt_text]
```

This is fragile on Windows, where command-line length limits are much lower than on POSIX shells. The review branch introduces large prompt-driven workflows and the contract test only exercises a tiny prompt string, so the first real multi-paragraph prompt can fail before the adapter even starts.

**Fix**: Feed prompt content via stdin or a temporary file instead of argv, and add a contract test that exercises a realistically large prompt on Windows-compatible execution paths.
