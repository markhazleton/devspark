# ADR-004: Tiered Prompt and Workflow Architecture

## Status

Accepted

## Context

DevSpark was a curated prompt library with implicit orchestration. Users hand-stitched command sequences manually, autonomy boundaries were unwritten, and there was no shared step-level telemetry or alias entrypoint. This created friction for beginners, inconsistent execution for experts, and no observability signal for workflow-level analysis.

## Decision

Re-platform DevSpark as a three-tier orchestration system: atomic prompts (`templates/prompts/atomic/`), workflow YAML definitions (`templates/workflows/`), and alias entrypoints (`templates/aliases/`). A Python workflow runner in `src/devspark_cli/runner/` enforces autonomy guardrails, emits JSON Lines telemetry, and pauses for human review at prescribed points. Three flagship workflows ship: `create-spec`, `execute-plan`, and `suggest-improvement`. All existing slash commands remain fully functional via 1:1 atomic prompt mappings.

## Consequences

### Positive

- Beginners have discoverable, high-level `devspark run <alias>` entrypoints.
- Autonomy boundaries are explicit and auditable; the runner is the single enforcement layer.
- JSON Lines telemetry enables workflow-level observability without external services.
- Backward compatibility is preserved: all 28 legacy slash commands still resolve.

### Negative

- Adds `pyyaml` dependency and a new `runner/` Python module.
- Thin atomic shim files must be kept in sync with command sources (shim-drift CI check added).
