# ADR-007: Harness Workflow Fixture as Spec Lifecycle Compliance Artifact

## Status

Accepted

## Context

The DevSpark harness runtime needed a validated sample workflow to demonstrate end-to-end execution of the spec-heading and spec-has-rationale validation rules. Rather than embedding fixture content outside the spec lifecycle, a lightweight spec artifact (`002-harness-runtime`) was created to satisfy harness validation rules while also demonstrating compliance with the spec lifecycle itself.

## Decision

Maintain `002-harness-runtime` as a dedicated fixture spec whose sole purpose is exercising the harness runtime's spec-validation rules. The spec is explicitly marked `Status: Complete` and carries a minimal task list. It is not a feature development spec and should not be extended with implementation tasks.

## Consequences

### Positive

- Harness sample (`sample.harness.yaml`) can run end-to-end with a real validated spec.
- Demonstrates spec lifecycle compliance by example.
- Low maintenance burden — no implementation tasks to track.

### Negative

- A permanent "fixture" spec directory in the lifecycle system may be confusing without the explicit `Complete` status and this ADR as context.
