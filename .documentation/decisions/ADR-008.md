# ADR-008: Prompt-Level Autonomy Override and the full-cycle Lifecycle

## Status

Accepted

## Context

Users chaining `specify → plan → tasks → critic → analyze` by hand reported two friction points: (1) command prompts ask the user to confirm at every gate even when the recommended option is obvious, and (2) critic and analyze findings had no path back into `tasks.md` — a human had to read both gate reports and manually decide what to fix. Resolving open findings required a separate, ad hoc merge step every time.

Separately, investigating "how do I automate this" surfaced an existing gap between intent and implementation: `templates/workflows/*.yaml` (consumed by `devspark run`) and `*.harness.yaml` (consumed by `devspark harness run`) are two different execution layers — a fact ADR-001 already flagged as a tracked architectural tension ("Two parallel execution layers... future consolidation may be warranted"). `devspark run`'s invoker only sequences and prints which prompt to invoke next; it does not call an LLM. Only the harness-runtime adapters (`claude_code`, `codex`, `copilot`, `cursor`) actually shell out to a CLI non-interactively. Additionally, `autonomy.level: autonomous` does not bypass a step's `pause_after`/`review_after` marker in the current `runner/executor.py` — only guardrail-breach severity differs by level. `.documentation/autonomy/autonomy-model.md` documented the bypass as if it worked; it did not.

## Decision

1. **Prompt-level `--auto` convention**: `implement.md`, `tasks.md`, `create-pr.md`, `quickfix.md`, `analyze.md`, `address-pr-review.md`, `specify.md`, and `clarify.md` each document an "Autonomy override" branch — when `--auto` (or a standing autonomy instruction) is in effect, the prompt auto-selects its own stated recommended option and records `auto-selected: true` under `## Gate Acknowledgements`, instead of waiting for a reply. Constitution/SHOWSTOPPER violations, quickfix FAIL findings, and `execution_mode: manual` findings are never auto-bypassed — autonomy controls *waiting*, not *judgment*.
2. **Gate Remediation Merge**: `/devspark.tasks` now detects whether `tasks.md` already exists. On a re-run, it merges `gates/critic.md` + `gates/analyze.md` findings (already in the Shared Review Resolution Contract shape from ADR-006-era work) into a deduped, severity-sorted `## Gate Remediation` task phase instead of regenerating from scratch. `/devspark.implement` flips a finding's `status` to `resolved` in its originating gate file when the task tagged `(resolves: <finding_id>)` completes.
3. **`full-cycle`**: a fourth workflow/alias pair (`templates/workflows/full-cycle.yaml`, `templates/aliases/full-cycle.yaml`) chaining all nine lifecycle steps with `autonomy.level: autonomous` and guardrails instead of `pause_after` markers — deliberately avoiding the workaround the gap above would otherwise require. A parallel `full-cycle.harness.yaml` provides the same chain as `agent_task` steps for genuine unattended execution via `devspark harness run --hands-off`, since the workflow-layer alias alone cannot execute without a driving agent present.
4. **Documentation correction**: `autonomy-model.md` now states the actual `pause_after`/`review_after` behavior rather than the aspirational one.

## Consequences

### Positive

- Users who want fewer checkpoints get an explicit, opt-in path (`--auto` for prompts, `full-cycle` for the whole lifecycle) without removing the safer assisted defaults for everyone else.
- Gate findings now have a closed loop: critic/analyze → tasks (remediate) → implement (resolve) → re-run critic/analyze, instead of dead-ending in a report no command ever reads back.
- The two-execution-layer gap from ADR-001 is now load-bearing in two places (`full-cycle` exists in both forms) rather than silently assumed away.

### Negative

- `--hands-off`'s automatic re-validation loop (`run_stage_revalidation_loop`) is currently telemetry/bookkeeping only — it does not re-invoke `critic`/`analyze` to regenerate findings. `full-cycle.harness.yaml` gets one remediation pass per run; deeper convergence still relies on the delivery-gate check to block `create-pr` rather than a true automatic loop. This is a known limitation, not a hidden one (documented in `harness-engineering.md`).
- `--auto` is a documentation-level convention enforced by prompt instructions, not a CLI flag the harness runtime parses — an agent not following the convention (or a careless edit to one of the eight files) silently reverts to interactive behavior. No machine-checkable test currently asserts all eight files retain the convention; consider a conformance check analogous to `prompt-conformance-manifest.md` if drift becomes a problem.
